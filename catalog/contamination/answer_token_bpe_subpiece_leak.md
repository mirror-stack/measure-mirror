# answer_token_bpe_subpiece_leak — 정답 토큰이 무관한 값의 BPE 조각으로 샌다

> The answer token leaks into the context as a BPE sub-piece of an unrelated value; string-level leakage checks pass clean because the answer never appears as a standalone string.

- **증상(시그니처)**: 문자열 수준 누설검사(경계 정규식·부분문자열 대조)는 **완전히 깨끗한데**,
  토큰 id 수준으로 세면 정답 토큰이 문맥에 더 있다. 채점이 **토큰 로짓**을 읽는 강제선택
  과제에서, 정답 문자열이 어디에도 독립적으로 안 나타나는데 특정 팔만 성능이 는다.
  누출률이 **채워 넣은 분량에 비례**해 커지면 거의 확정(용량축과 오염축이 겹친다).
- **기전**: 생성기가 "이 값은 단일 토큰"을 **고립 상태에서** 검증한다(`encode(' 187')` 길이 1).
  그러나 BPE는 문자열 전체에 대해 돌기 때문에 **실제 문맥에서는 병합이 달라진다** —
  `'. 50: 187. '`은 `' 18' + '7'`로 쪼개져 표적 18의 **정답 토큰 `' 18'`이 문맥에 생긴다.
  문자열 `18`은 독립된 숫자로 등장한 적이 없으므로 `(?<!\d)18(?!\d)` 같은 경계검사는
  **정상적으로** 통과한다. 두 게이트가 서로 다른 답을 내고, **느슨한 쪽이 통과시킨다.**
- **실사례**: (결속벽 무대 서식블록 아크, 08-04~05) 무봉인 진단 E21의 주입 게이트가 16건을
  울려 채널이 드러났고, **이미 봉인된** E20에도 같은 채널이 있었다 — 블록 팔 **4.13%** vs
  블록 없는 팔 **0.00%**의 **차등 오염**이고 방향이 보고된 효과와 같았다. E21 쪽은
  **용량축과 정확히 함께** 커졌다(1행 1.5% → 4행 2.8% → 8행 4.5% → 16행 6.5%).
  E20의 원 주입 게이트는 **floor 팔 기준 상대형**이었는데 floor는 설계상 정답을 포함해
  여유가 있었고, 그래서 팔의 2회 출현을 **가려 통과시켰다**. 오염 차단(블록 값을 후보 토큰
  0개가 될 때까지 재추출) 후 재봉인: 주지표 **+0.2900 → +0.2512**(CI 겹침·판정 불변
  PASS_decisive)이나 **부수 주장 1건은 소멸해 철회**(`near_full−near_scram` +0.0300
  [0.0075,0.0525] → +0.0125 [−0.0125,0.0387]). ★부수효과: 다시드 **CV 25.54% → 8.63%**로
  WARN 해소 — 오염이 시드 간 변동의 큰 몫이었다.
  출처: 자가적발 am `948006b1` · 원 봉인 `d0a00041`/am `fb6bd4e9` · 수정 봉인 `b83deab5`/am `3afc0379`.
- **탐지법**: ①**채점이 읽는 단위로 세라.** 채점이 토큰 로짓이면 누설검사도 **토큰 id**로 한다
  (문자열 검사는 필요조건이지 충분조건이 아니다). ②**절대형 게이트**를 써라 — "정답 토큰이
  각 팔에 정확히 k회"로 못박는다. **오염 가능성이 있는 팔(정답을 설계상 포함하는 기준 팔)에
  대한 상대형 게이트는 게이트가 아니다.** ③단일토큰 검증은 **고립이 아니라 실제 조립 문자열**
  에서 하라(`encode('. ' + row)`). ④봉인 전 전 팔·전 에피소드 오프라인 계수(모델 불필요·쌈).
  ⑤두 게이트가 불일치하면 **엄한 쪽이 이긴다** — 느슨한 쪽을 근거로 통과시키지 마라.
- **오적용 주의**: ①정답이 **설계상** 문맥에 있는 팔(값블록·오라클 배치)에서 2회 나오는 것은
  오염이 아니다 — 팔별 **정당 기대치**를 먼저 정의하고 초과분만 센다. ②병합 때문에 정답
  토큰이 **사라지는**(기대 2회인데 1회) 경우도 있다. 이건 누설이 아니라 계기 변동이므로
  같은 라벨로 묶지 마라. ③차등 오염이 확인돼도 **결론이 자동 무효는 아니다** — 이 실사례에서도
  주지표는 살아남았다. 재실행 없이 "오염됐으니 폐기"도, "작으니 괜찮다"도 둘 다 성급하다.
  ④수정 재실행이 **오염 제거 외의 것까지 바꾸면**(여기선 블록 값 전체 재추출) 두 값의 차이를
  "오염 몫"으로 귀속하지 마라 — 이 아크에서 내가 낸 경계(≤+0.012)가 실제 차이(−0.0388)에
  3배 어긋난 이유가 정확히 그것이다.
